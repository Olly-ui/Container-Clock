Roadmap in three phases

Each phase starts only after the one before it has shown it works with real agents. The ideas so far come from one interview with a freight forwarder and the published tariffs.

Phase 1Screens ready

The agent clock

For clearing agents. Works with data the agent enters.

  • Two clocks: terminal storage and line demurrage
  • Daily cost with the real step-ups in the published rates
  • Steps list before release
  • Alerts before charges start
  • Stage log with dates
  • Field for the terminal charge statement and any waiver

Data needed: Agent entry, and published terminal and shipping line tariffs. We have four terminals and two line schedules so far.

Must prove: Agents lose money to delays they can avoid, and will enter data.

Phase 2Needs data access

Port activity view

One view of what the shipping line and the terminal show for each container.

  • Vessel, line and terminal status in one place
  • Storage, demurrage and detention days per container
  • Vessels expected, by shipping line
  • Link to the line or terminal tracking page

Data needed: Line and terminal tracking pages, or agreements to share data.

Must prove: Lines and terminals will share data, or public pages can be read.

Phase 3Needs data access

Trucks, exports and network

Extends to the port corridor, exports, and the link between importers and agents.

  • Truck call-up status for import pick-up
  • Export containers and the export processing terminal
  • Importers post jobs, licensed agents respond
  • Other services, once the clock is in use

Data needed: Call-up data from the port authority, and licensing checks for agents.

Must prove: Outside developers can get the data, and users want the network.
